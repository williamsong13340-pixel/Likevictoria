# 技术架构

> 版本 v0.3。描述"怎么把设计变成又快又好看的程序"。经济模型的数学与取舍单独见 [经济模型](04-economic-model.md)。

## 1. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript 6（全栈），Node 直接运行 `.ts` | 模拟与界面一种语言；不需要编译步骤；浏览器与 Node 都能运行，方便测试与批量仿真 |
| 为什么不是 TypeScript 7 | 7.0 是 Go 重写版，其 JS 编译器 API 仍是不稳定接口 | 自研静态分析与 typescript-eslint 都依赖编译器 API |
| 模拟内核 | 纯 TS 库，运行在 Web Worker 中 | 与界面线程分离，界面不卡；同一份代码可以无头运行 |
| 数据布局 | 结构数组（SoA）+ TypedArray | 缓存友好、序列化快；性能热点以后可以平滑迁移到 Rust/WASM |
| 界面 | React + Vite + Zustand + ECharts | 大战略游戏的大部分界面是面板、表格和图表，Web 生态在这方面最强 |
| 地图 | WebGL2 自研渲染器（见第 6 节） | 画面完全可控，切换地图模式几乎零成本 |
| 内容数据 | YAML + Schema 校验 → 构建时编译为紧凑格式 | 易编辑、易做模组、报错清晰 |
| 桌面发行 | Electron | 自带 Chromium，各平台的 WebGL/WebGPU 表现一致，适合对画面和帧率有要求的游戏 |
| 质量护栏 | TypeScript 严格模式、ESLint、Prettier、Knip、自研静态分析、Vitest、对抗性审查子代理 | 见第 8 节 |
| 工程 | pnpm workspace monorepo；GitHub Actions CI | |

## 2. 仓库结构

```
likevictoria/
├─ packages/
│  └─ sim/                  # 模拟内核：纯逻辑，不依赖 DOM，确定性
│     ├─ src/macro/         #   宏观块、需求替身、场景、沙盒运行器
│     └─ test/              #   经济规律测试
├─ tools/
│  ├─ headless/             # 命令行：宏观沙盒（以后是完整的无头仿真）
│  ├─ analysis/             # 自研静态分析：无用字段、纯转发函数
│  └─ art/                  # 出图工具（OpenAI 图像接口）
├─ art/style-samples/       # 美术风格样图及其提示词
├─ docs/                    # 设计文档
└─ .claude/agents/          # 对抗性审查子代理
```

之后按里程碑加入 `packages/ui`（界面与地图渲染）、`packages/data`（内容数据）、`tools/map-pipeline`（地图管线）、`tools/calibrate`（历史校准）。原则是需要时才加，不预先建空目录。

## 3. 模拟内核

### 3.1 状态与系统

- 全部游戏状态放在一个**可序列化的状态容器**中，按实体类型以 SoA 存储（如 `pop.size: Float64Array`），实体用整数 ID 索引。
- 逻辑写成一组**系统**（读状态 → 写状态），按固定顺序执行。系统之间只通过状态通信，可以单独测试。宏观块已经是这种形式：`stepMacro(state, policy, inputs, params)` 是纯函数。
- **修正项与因果分解**：每个关键数值都由带来源标签的修正项叠加而成。界面上"每个数字都能解释"就靠它，所以它是数据结构的一部分，而不是事后补的调试功能。

### 3.2 回合管线

每周（微观层）：命令生效 → 劳动力匹配 → 生产 → 国内市场临时均衡 → 国际贸易 → 收入分配 → 消费与储蓄 → 投资 →（调试模式）不变量校验。

每月：宏观块（每国一步）、迁移、政治、外交与危机回合、冲突结算。

每年：人口队列推移、教育升级、技术扩散、气候、按日程举行的选举。

### 3.3 确定性

- 固定的系统执行顺序与实体遍历顺序；随机数来自带种子的生成器，每个系统使用独立的随机流。
- ESLint 在 `packages/sim` 中禁止 `Math.random`，以及 `Date`、`performance`、`crypto`、`process`、`globalThis` 等全局量（无论通过哪种写法访问）。
- 跨引擎：`Math.exp`、`Math.tanh` 在不同 JavaScript 引擎上可能有最后一位的差异。Node 与 Electron 都是 V8，所以结果一致；如果将来要在其他引擎上回放，再自带这些函数的实现。
- 好处：Bug 可以复现，可以回放，可以做批量实验和 A/B 平衡对比。

### 3.4 命令与快照

- 模拟在 Web Worker 中运行，每回合结束后向界面发送**只读快照**（当前界面需要的数据切片）与统计时间序列的增量。
- 玩家与 AI 的操作都以**命令**形式发给模拟，在下一回合开始时统一生效。这同时是回放、自动化测试与将来联机的基础。
- 存档 = 状态容器序列化（二进制 + 压缩）+ 版本号与迁移脚本。

## 4. 经济模型

见 [经济模型](04-economic-model.md)。要点：微观层每回合做临时均衡、只决定实物量与相对价格；宏观块每月一组方程，决定通胀、利率、汇率与债务；两层通过少数变量耦合；每个参数有含义、单位与范围；可能发散的响应有界；不稳定的更新改为隐式求解。

## 5. 数据与模组

- 内容文件用 YAML 编写；构建时做 Schema 校验（引用完整性、数值范围、单位），编译为运行时格式。
- 每个定义有稳定的字符串 ID（如 `good.steel`、`law.central_bank.independent`），存档与模组通过 ID 引用。
- 模拟代码不硬编码内容 ID（ESLint 拦截），只通过配方、需求类别与标签接触内容。新增商品与法律只改数据，详见 [内容目录](05-content-catalog.md)。
- 模组 = 覆盖或追加数据文件 + 本地化文本；后期再考虑受限的事件脚本（不允许执行任意代码）。

## 6. 地图：精美与速度

### 6.1 管线

1. **来源**：Natural Earth（公有领域）的国家与一级行政区边界；地形用公有领域栅格（Natural Earth 的晕渲地形与分层设色、NOAA ETOPO 高程与海深）。
2. **地区划分**：合并过小的行政区、拆分过大的行政区，在 1946 年的分界线（占领区、分界线）处手工切分，得到约 1,000—1,500 个地区，记录名称、中心点、面积、邻接与海岸。
3. **开局归属**：为每个地区标注 1946 年的控制者与法理状态（主权国家、殖民地、托管地、占领区）。
4. **运行时资源**：地区 ID 纹理、边界折线、标签位置、邻接图、地形纹理与法线贴图。
5. 历史边界数据集（如 CShapes）可以作参考，但必须逐一核对许可证是否允许商业使用。

### 6.2 渲染

| 层 | 做法 | 为什么好看、为什么快 |
|---|---|---|
| 地形 | 高程生成法线贴图，在着色器中实时光照；分层设色与海深渐变；细微的动态水面 | 山川有立体感；光照方向和色调可以随美术风格调整 |
| 政治着色 | 地区 ID 纹理 + 颜色查找纹理（每个地区一个像素），半透明叠加在地形上 | 切换地图模式只需更新一张很小的纹理，耗时不到一帧 |
| 边界 | 矢量折线三角化，屏幕空间等宽、抗锯齿；国界与地区界分级 | 任何缩放级别都清晰 |
| 文字 | 国家名沿形状主轴弯曲排布；中文用 Canvas 2D 叠加层绘制 | 避免巨大的中文字体图集，排版质量高 |
| 细节层级 | 按缩放级别切换边界精度、标签与图标密度 | 远看清爽，近看细致 |
| 后期效果 | 按选定风格：纸张纹理、暗角、柔光等 | 风格统一 |

性能目标：中端显卡 60 帧；地图模式切换不掉帧；界面中的长表格使用虚拟列表，图表用 Canvas 渲染。用 Playwright 截图做视觉回归测试，保证改动不会悄悄破坏画面。

### 6.3 规模与性能预算

| 实体 | 数量级 |
|---|---|
| 地区 | 1,000—1,500 |
| 人口学格子 | 地区×族群（约 3,000—5,000）× 202 个年龄—性别格，每年更新一次 |
| Pop | 约 3 万—6 万 |
| 建筑 | 约 2 万—4 万 |
| 价格 | 约 100 种商品 × 200 个市场 = 2 万个 |

目标：中端 PC 上，游戏后期最高速每游戏年不超过 30 秒。按以上规模，每个周回合大约是百万次量级的数值运算，TypeScript + TypedArray 足够；超出预算的热点再迁移到 Rust/WASM。性能预算纳入 CI，防止退化。

## 7. 美术素材管线

- 出图使用 OpenAI 的 `gpt-image-2.6-sunburst`：`pnpm art --prompt-file <提示词.md> --out <图片.webp>`。提示词文件开头写明模型、尺寸、质量，与图片放在一起；生成没有种子，所以复现的是同样的请求，而不是同样的像素（`art/style-samples/` 中最早的三张样图由 2.5 版生成）。
- 改图模式：提示词开头写 `input: 底图.png` 时，工具调用图像编辑接口，在底图上改风格。界面样张用同一张"真实世界地图 + 界面线框"做底图，所以各时代的样张地理准确、布局一致。
- 省着用：先出少量样张让用户确认风格，再批量制作图标与界面素材。
- 生成图中的地图边界和文字不能直接作为素材：地图由真实数据渲染，文字由游戏渲染。

## 8. 质量护栏

### 8.1 静态分析（`pnpm check`）

| 检查 | 工具 | 抓什么 |
|---|---|---|
| 类型 | TypeScript 严格模式（含 `noUnusedLocals`、`noUnusedParameters`、`exactOptionalPropertyTypes`、`noUncheckedIndexedAccess`） | 类型错误、未使用的局部变量与参数 |
| 代码规则 | ESLint（typescript-eslint 严格类型检查规则） | 可疑写法；模拟内核中的不确定性来源（随机数、系统时间、各种全局量）；硬编码的内容 ID（含模板字符串） |
| 格式 | Prettier | 格式一致 |
| 无用代码 | Knip 普通模式 | 未使用的文件、导出、类型、依赖 |
| 只被测试使用的代码 | Knip 生产模式 | 生产代码里只有测试在用的导出 |
| 无用字段 | 自研分析（`tools/analysis`） | 接口、类型字面量、类、普通对象常量中**只写不读**的字段。只在测试里读、只为计算自己的下一期值而读、只在类型层面引用，都不算读；`++`、`+=` 算写入 |
| 纯转发函数 | 自研分析 | 只把参数原样转发给另一个函数或构造函数的包装（包括剩余参数、类属性、对象属性、类型断言等写法；带默认参数或为实现接口而存在的方法除外） |
| 无用内容数据 | 内容校验（随内容系统实现，**尚未启用**） | 没人生产或没人消费的商品、没人读取的修正键 |

以上已启用的检查都做过"注入一个问题，确认它能被抓到"的反向验证。

### 8.2 测试

1. **对照测试**：每条声称的经济规律一个测试，两次运行只差一个机制（见经济模型文档第 7 节）。
2. **变异测试**：故意删掉或改坏一个机制，确认至少一条测试会失败；没有测试能证明其作用的机制，要么补测试，要么删掉。
3. **属性测试**：全部参数在文档范围内随机抽样，每个场景跑满 100 年，要求结果有限、有界、没有高频振荡；以及任意参数下，自洽的稳态保持不动。
4. **不变量测试**：国际收支恒等式（固定汇率下储备变化 = 经常账户 + 资本流动）；之后加入资金守恒、人口守恒。
5. **无头批量仿真**：命令行跑完 1946—2045，输出表格；多个随机种子看分布。
6. **历史校准**：以公开数据为目标自动调参，例如世界人口 1950 年约 25 亿 → 2020 年约 78 亿，以及各国的人均 GDP、城市化率、预期寿命、总和生育率、产业结构轨迹。可用数据源（使用前须核对许可证）：联合国《世界人口展望》、Maddison Project、Penn World Table、世界银行 WDI、V-Dem、Our World in Data。

### 8.3 对抗性审查

`.claude/agents/adversarial-reviewer.md` 定义了一个只读的审查子代理（Opus，max effort）：它的任务是证明改动是错的——跑命令、写一次性实验、用随机参数、延长运行和篡改实现去证伪，并给出带证据的发现。较大的改动在提交前都要经过它。第一轮审查发现的问题与修正，见经济模型文档第 10 节。

## 9. 主要技术风险

| 风险 | 对策 |
|---|---|
| 经济模型不稳定 | 临时均衡、半衰期、有界响应、隐式求解、规律测试、参数扫描 |
| 复杂到玩家看不懂 | 因果分解从第一天起就是数据结构的一部分 |
| 性能 | SoA 布局、Worker、CI 性能预算、热点迁移 WASM |
| 开局数据工作量巨大 | 数据管线 + 自动校准（根据目标 GDP 与产业结构反推初始建筑配置） |
| AI 生成代码的冗余与"看起来对" | 静态分析 + 对抗性审查 + 规律测试 |
