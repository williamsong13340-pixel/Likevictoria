# 技术架构

> 版本 v0.1 · 草案。描述"怎么把设计文档变成能跑的程序"。公式都是初版，需要在原型中校准。

## 1. 技术选型（推荐）

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript（全栈） | 模拟与界面用同一种语言；迭代快；浏览器和 Node 都能运行，方便测试与批量仿真 |
| 模拟内核 | 纯 TS 库，在 Web Worker 中运行 | 与界面线程分离，界面不卡；同一份代码可以在 Node 里无头运行 |
| 数据布局 | 结构数组（SoA）+ TypedArray | 缓存友好、序列化快；性能热点以后可以平滑迁移到 Rust/WASM |
| 界面 | React + Vite + Zustand + ECharts | 大战略游戏大部分是面板、表格和图表，Web 生态在这方面最强 |
| 地图 | WebGL2（自研薄封装或 PixiJS） | 地区 ID 纹理 + 颜色查找表着色器，切换地图模式几乎零成本 |
| 内容数据 | YAML + zod 校验 → 构建时编译为紧凑格式 | 易编辑、易做模组、报错清晰 |
| 测试 | Vitest；无头批量仿真；历史校准 | 见第 8 节 |
| 桌面发行 | Tauri（后期） | 体积小，可以上 Steam；网页版可以做试玩 |
| 工程 | pnpm workspace monorepo；GitHub Actions CI | |

> 如果更倾向于 Godot、Unity 或 C++，第 2 节以后的架构（模拟与界面分离、数据驱动、确定性、校准方法）同样适用，只是实现语言不同。

## 3. 模拟内核

### 3.1 状态与系统

- 全部游戏状态放在一个**可序列化的状态容器**中，按实体类型以 SoA 存储（如 `pop.size: Float64Array`、`pop.region: Uint16Array`），实体用整数 ID 索引。
- 逻辑写成一组**系统**（读状态 → 写状态），按固定顺序执行。系统之间只通过状态通信，可以单独测试。
- **修正项与因果分解**：每个关键数值（价格、产出、满意度、合法性……）都由带来源标签的修正项叠加而成。这不是事后补的调试功能，而是数据结构的一部分——界面上"每个数字都能解释"就靠它。

### 3.2 回合管线

每周：

```
1. 命令生效      玩家与 AI 的命令（法律、预算、利率、关税、条约……）
2. 劳动力市场    岗位匹配、工资调整、失业与非正规部门
3. 生产          按投入与劳动力的满足率计算各建筑产出
4. 国内市场      供需 → 价格调整（库存缓冲、价格管制、配给）
5. 国际贸易      各国贸易量与世界价格调整 → 双边流量分配
6. 收入分配      工资、利润、地租、利息、转移支付、税收
7. 消费与储蓄    Pop 按收入与价格购买需求篮子
8. 金融          信贷、利息、外汇市场与汇率、储备
9. 投资          私营 / 国有 / 外资的扩建与关停
10. 校验         （调试模式）资金守恒、人口守恒、无 NaN
```

每月追加：迁移、政治（社会力量支持度、运动、合法性）、外交（影响力、关系、危机回合）、冲突结算。
每年追加：人口队列推移（出生、死亡、年龄增长、教育升级）、技术扩散、气候、选举（按选举日程）。

### 3.3 确定性

- 固定的系统执行顺序和实体遍历顺序；所有随机数来自带种子的伪随机数生成器，每个系统使用独立的随机流。
- 不依赖对象键顺序、`Math.random` 或系统时间。
- 好处：Bug 可以复现，可以回放，可以做批量实验和 A/B 平衡对比。联机如果采用"主机权威 + 状态同步"，就不需要跨平台浮点逐位一致。

### 3.4 命令与快照

- 模拟在 Web Worker 中运行，每个回合结束后向界面发送**只读快照**（当前界面需要的数据切片）和统计时间序列的增量。
- 玩家操作以**命令**形式发给模拟（如 `SetLaw`、`SetBudget`、`ProposeTreaty`），在下一个回合开始时统一生效。AI 也走同一条命令通道——这同时是回放、自动化测试和将来联机的基础。
- 存档 = 状态容器序列化（二进制 + 压缩）+ 版本号与迁移脚本。

## 4. 经济模型（初版数学）

### 4.1 生产

```
产出_b   = 级别_b × 利用率_b × 基础产出(生产方式) × 生产率乘数_b
利用率_b = min(劳动力满足率, 投入品满足率) × 盈利调节
```

投入按固定比例（里昂惕夫式）消耗；长期亏损的建筑逐步降低利用率，最终关停或降级。生产率乘数是一组修正项：技术、基础设施、管理质量（所有制与国家能力）、气候与环境。

### 4.2 消费需求

采用**线性支出系统（LES）**：先满足每个需求类别的"最低消费量"，剩余收入按边际预算份额分配：

```
x_i = γ_i + (β_i / p_i) × (Y − Σ_j p_j γ_j)
```

类别内部按相对价格替代（如燃料：煤 / 油 / 气 / 电）。这样**恩格尔定律**（越富裕，食物支出占比越低）会自然出现。

**储蓄率**取决于：年龄结构（生命周期：工作年龄储蓄、退休后消耗储蓄）、利率、收入水平，以及社会保障程度（保障越弱，预防性储蓄越高）。

### 4.3 价格调整

每个市场、每种商品，采用带库存缓冲与阻尼的摸索过程：

```
ln p(t+1) = ln p(t) + k × (D − S) / max(D, S) − k_inv × (I − I*) / I*
```

D 为需求，S 为供给（含进口），I 为库存，I* 为目标库存；单回合涨跌幅设上限，避免价格振荡。价格管制的商品价格固定，供需缺口通过配给（按优先级分配）体现，部分溢出为黑市。

### 4.4 劳动力市场与迁移

- 劳动力池按"地区 × 受教育层级"划分，与岗位匹配；高学历可以向下就业。
- 工资：岗位空缺多则上涨，失业多则下降；下降比上涨慢（名义刚性），受最低工资与工会约束。
- 城乡与地区间迁移使用**哈里斯—托达罗模型**：

```
期望城市收入 = 城市工资 × (1 − 城市失业率)
```

与农村收入比较，扣除迁移成本和政策壁垒后决定迁移流量。

### 4.5 国际贸易（两步）

1. **贸易量与世界价格**：每种商品有一个世界价格。若某国国内价格高于"世界价格 ×（1 + 贸易成本）"，进口量增加；低于"世界价格 ×（1 − 贸易成本）"，出口量增加；贸易成本 = 运输 + 关税 + 非关税壁垒。世界价格本身也像国内价格一样逐回合调整，使全球净出口趋于零。复杂度约为"国家数 × 商品数"。集团对立时，可以存在多个相互之间摩擦很高的"贸易圈"，各有自己的世界价格。
2. **双边流量**：用**引力模型**把各出口国的出口量分配给各进口国，权重由距离、关系、协定与制裁（禁运时权重为零）决定。双边流量用于计算依赖与筹码，并反馈到下一回合的有效贸易成本。

### 4.6 货币与宏观（存量—流量一致）

- 采用**存量—流量一致（SFC）**的记账方式：每一笔流量都有付款方和收款方，每个部门（家庭、企业、银行、政府、央行、外国）都有资产负债表。钱不会凭空出现或消失；唯一的"创造"渠道是银行信贷与央行操作——这正是通胀与金融周期的来源。
- 名义价格直接在市场中形成，所以通胀是涌现的；工资设定包含通胀预期（适应性预期 + 央行信誉），由此产生通胀惯性。
- **汇率**：浮动制下由外汇供求（经常账户 + 资本流动）决定；资本流动对利差、风险与预期敏感，并受资本管制约束；钉住制下央行用储备干预，储备不足时投机攻击的概率上升。
- **备选方案**：如果完全涌现的通胀在调参后仍然不稳定，就退回"相对价格（由市场决定）× 价格水平（由宏观方程决定）"的混合模型。

### 4.7 人口学（队列—要素法）

每年对每个"地区 × 族群"：

- 按单岁年龄、分性别推移一年，乘以各年龄的存活率。
- 出生数 = Σ 各年龄育龄女性人数 × 年龄别生育率；年龄别生育率 = 总和生育率 × 标准生育年龄分布（平均生育年龄随女性受教育程度推迟）。
- 各年龄死亡率由**模型生命表**（Brass 关系模型）根据当前的健康水平生成。
- 净迁移来自迁移系统；教育升级按入学率把各年龄人口推入更高的受教育层级。

### 4.8 规模与性能预算

| 实体 | 数量级 |
|---|---|
| 地区 | 1,000—1,500 |
| 人口学格子 | 地区×族群（约 3,000—5,000）× 202 个年龄—性别格，每年更新一次 |
| Pop | 约 3 万—6 万 |
| 建筑 | 约 2 万—4 万 |
| 价格 | 约 50 种商品 × 200 个市场 = 1 万个 |

目标：中端 PC 上，游戏后期最高速每游戏年 ≤ 30 秒。按以上规模，每个周回合大约是百万次量级的数值运算，TypeScript + TypedArray 足够；超出预算的热点再迁移到 Rust/WASM。性能预算纳入 CI，防止退化。

## 5. 数据与模组

- 内容文件放在 `packages/data`，用 YAML 编写；构建时用 zod 校验（引用完整性、数值范围、单位），编译成运行时格式。
- 每个定义有稳定的字符串 ID（如 `good.steel`、`building.steel_mill`、`law.central_bank.independent`），存档与模组都通过 ID 引用。
- 模组 = 覆盖或追加数据文件 + 本地化文本。后期再考虑一个受限的脚本语言用于事件条件与效果（不允许执行任意代码）。

数据示例——纺织厂的两种生产方式（数值为占位）：

```yaml
id: building.textile_mill
category: light_industry
construction_cost: 400            # 以"建设"服务计
production_methods:
  - id: pm.textile.mechanical_looms
    unlocked_by: tech.mechanized_textiles
    inputs:  { good.fiber: 20, good.electricity: 5 }
    outputs: { good.clothing: 30 }
    jobs:    { primary: 400, secondary: 20 }      # 按最低受教育层级划分的岗位数
  - id: pm.textile.automated_lines
    unlocked_by: tech.industrial_robotics
    inputs:  { good.fiber: 20, good.electricity: 12, good.machinery: 2 }
    outputs: { good.clothing: 45 }
    jobs:    { primary: 120, secondary: 30, tertiary: 10 }
```

## 6. 地图管线

1. **来源**：以 Natural Earth（公有领域）的国家与一级行政区边界为基础。
2. **地区划分**：合并过小的行政区、拆分过大的行政区，并在 1946 年的分界线（占领区、分界线）处手工切分，得到约 1,000—1,500 个地区；每个地区有 ID、名称、中心点、面积、邻接关系与海岸标记。
3. **开局归属**：为每个地区标注 1946 年的控制者与法理状态（主权国家、殖民地、托管地、占领区）。
4. **生成运行时资源**：地区 ID 纹理、边界线、标签位置、邻接图。
5. **渲染**：着色器读取像素的地区 ID，再去颜色查找纹理（每个地区一个像素）取色。切换地图模式只需要更新这张很小的查找纹理。
6. 历史边界数据集（如 CShapes）可以作为参考，但必须逐一核对许可证是否允许商业使用。

## 7. 界面原则（技术侧）

- 界面只读快照、只发命令，从不直接修改模拟状态。
- 所有数值展示组件都支持展开"因果分解"（来自 3.1 的修正项）。
- 图表统一使用时间序列存储：每个国家的关键指标按月记录，长期按年降采样，控制内存。

## 8. 测试与历史校准

这是让"复杂经济模拟"保持可控的关键：

1. **单元测试**：每个系统单独测试（价格收敛、LES 需求、队列推移、汇率干预……）。
2. **不变量测试**：每回合资金守恒（各部门资产负债表加总为零）、人口守恒（出生 − 死亡 ± 迁移）、没有 NaN 和负数。
3. **无头批量仿真**：在命令行跑完 1946—2045，输出 CSV 与图表；用不同随机种子跑多次，看结果的分布。
4. **历史校准**：把公开数据当作"考试题"，例如：
   - 世界人口：1950 年约 25 亿 → 2020 年约 78 亿；
   - 各国与各地区的人均 GDP 轨迹、城市化率、预期寿命、总和生育率、产业结构（农业 / 工业 / 服务业占比）；
   - 去殖民化、冷战格局变化等宏观事件出现的时间区间。

   目标不是逐年复现历史，而是让 AI 自动运行的结果落在合理区间内，同时保留偏离历史的可能。
5. **参数扫描**：自动扫描关键参数，找出稳定区域，避免"改一个参数全盘崩溃"。

可用的公开数据源（使用前须核对许可证）：联合国《世界人口展望》、Maddison Project（历史 GDP）、Penn World Table（资本与生产率）、世界银行 WDI、V-Dem（政治制度）、Our World in Data、Natural Earth（地图）。

## 9. 主要技术风险

| 风险 | 对策 |
|---|---|
| 经济模型不稳定（价格振荡、通胀失控、通缩螺旋） | 库存缓冲、阻尼与限幅、SFC 记账、不变量测试、参数扫描 |
| 复杂到玩家看不懂 | 因果分解从第一天起就是数据结构的一部分 |
| 性能 | SoA 布局、Worker、CI 性能预算、热点迁移 WASM |
| 开局数据工作量巨大 | 数据管线 + 自动校准（根据目标 GDP 与产业结构反推初始建筑配置） |
